# Torn Company Training Manager v1.1 Reliability & Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.1.0 with a reliable user-triggered Torn training POST, cache-aware verification, diagnostics, explicit update metadata/changelog, and a local 500-entry action audit log/UI.

**Architecture:** Keep the current controller/policy separation. Add a small audit core/storage boundary, change only the training page-action transport, extend controller state transitions and diagnostics, add one audit-log UI module, and make package.json the single release-version source used by the build.

**Tech Stack:** Vanilla JavaScript ES modules, Node 20 test runner, jsdom, esbuild, Tampermonkey GM storage, Torn API v2, same-origin Torn company page POST.

**Spec:** `docs/superpowers/specs/2026-09-08-v1.1-reliability-audit-design.md`

## Global Constraints

- Release version is exactly `1.1.0`.
- Inactivity remains strictly `> 86400` seconds; exactly 24 hours stays eligible.
- Addiction remains ineligible only when magnitude is strictly greater than configured maximum.
- No automatic or unattended Torn writes.
- Every Torn write remains explicitly user-triggered and confirmation-gated.
- Audit data is local-only and retains at most 500 entries.
- Never persist API keys, RFC tokens, cookies/session data, authorization headers, or raw authenticated response bodies in diagnostics/audit.
- Existing v1.0.6 floating manager, minimize/maximize, gear settings, route detection, payroll safety, and global badge must remain working.
